## 三、补全策略说明

### 3.1 两层策略

1. **深度补全（丰富生平）**：针对 61 位有详细生平描述（description > 100字且非模板文字）的人物，生成包含完整生平描述的高质量事件（importance=4）。

2. **基础补全（生平概要）**：针对其余人物，从 summary 和生卒年数据中提取关键信息，生成「生平」事件（importance=2-3）。

### 3.2 时间处理逻辑

| 情况 | 处理方式 |
|------|---------|
| 有确切生卒年 | 事件覆盖 [birthYear, deathYear]，`isApproximate: false` |
| 仅有生年 | 假定享年60岁，`isApproximate: true`，summary 中注明「卒年不详，假定约享年60岁」 |
| 仅有卒年 | 假定享年60岁，`isApproximate: true`，summary 中注明「生年不详，假定约享年60岁」 |
| 生卒年均不详 | 从 summary 文本中提取提及年份，±30年作为活跃时期，`isApproximate: true` |
| 完全无法确定时间 | 跳过（元朝 6,641 人因此被跳过） |

### 3.3 时间模糊性说明

所有 `isApproximate: true` 的事件，其 `summary` 字段末尾均包含时间说明，例如：
- 「（时间说明：卒年不详，假定约享年60岁）」
- 「（时间说明：生卒年均不详，根据史料中提及的年份推断大致活跃时期）」

前端可在事件卡片中展示此说明，帮助用户理解时间的模糊性。

## 四、数据存储架构

### 4.1 存储方式

新增事件以 JSON 格式存储于 `src/data/events/` 目录，共 116 个批次文件：
- 每个文件包含 500 个事件（最后一批 99 个）
- 文件命名：`_lifespanEvents1.json` ~ `_lifespanEvents116.json`
- 通过 `mockData.ts` 中的 import + spread 语法合并到 `events` 数组

### 4.2 为什么用 JSON 而非 TypeScript

初期尝试直接生成 TypeScript 文件，但遇到 TypeScript 类型推断复杂度限制（TS2590 错误）。JSON 导入不触发类型推断，完美解决此问题。

### 4.3 事件 ID 命名规则

格式：`evt-lifespan-{personId}`
- 与人物一一对应，每个 ID 唯一
- 与原有事件 ID（`evt-xxx` 格式）无冲突
